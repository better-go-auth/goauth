# Phase 2 - Round 2 (2026-10-17) - what was done and what remains

## Done in this round

### Org parity - team/organizationRole (opt-in, backwards compatible)
- `src/models/tables.go`: added `ModelTeam`, `ModelTeamMember`, `ModelOrganizationRole` constants.
- `src/plugins/org/models/organization.go`: added `Team`, `TeamMember`, `OrganizationRole` models (better-auth spec: `team`, `teamMember`, `organizationRole`). `Team` has `name+organizationId`, `TeamMember` has `teamId+userId`, `OrganizationRole` has `organizationId+role+permission(JSON)` replacing legacy `OrgPermission` (role/resource/action rows). All use `coremodels.TableName()` so `GoAuth.TablePrefix`/`TableNames` applies. Legacy `OrgPermission` stays commented out.
- `src/plugins/org/repository/interfaces.go`: added `ITeamRepo`, `ITeamMemberRepo`, `IOrganizationRoleRepo` interfaces; extended `OrgRepositories` and `IOrgRepos` to carry them.
- `src/plugins/org/repository/gorm/team_repo.go` (new): GORM repos `TeamRepo`, `TeamMemberRepo`, `OrganizationRoleRepo` (create/get/list/update/delete, Tx for team delete).
- `src/plugins/org/repository/gorm/gormutil.go`: `NewOrgRepos` now wires the three new repos.
- `src/plugins/org/repository/gorm/gorm_migrator/migrator.go`: `AutoMigrate` now includes `Team`, `TeamMember`, `OrganizationRole`.
- `src/plugins/org/config/config.go`: added `TeamsConfig {Enabled, DefaultTeam, MaximumTeams, MaximumMembersPerTeam, AllowRemovingAllTeams}`, `DynamicAccessControlConfig {Enabled}`, and `OrgConfig` fields `Teams`, `DynamicAccessControl` plus compat stubs `AllowUserToCreateOrganization`, `OrganizationLimit`, `CreatorRole`, `MembershipLimit`, `InvitationLimit`. When `Teams` is nil/disabled, tables still migrate but team endpoints should 404 and `invitation.teamId` is ignored (enforcement is next step).
- `invitation.teamId` and `session.activeTeamId` were already present from earlier rounds.

### CI - official `better-auth/client` (step 3, done-when)
- `.github/workflows/ci.yml` (new): two jobs. `vet` runs `go vet ./...` + `golangci-lint`. `compat` sets up Go+Node, `npm install` in `src/tests/compat/client`, then `go test -run TestOfficialBetterAuthClient -count=1 -timeout 120s` (covers `TestOfficialBetterAuthClient`, `_Bearer`, `_JWT` in `src/tests/compat/client_test.go`). Uses `go-version-file: goauth/go.mod`.
- `src/tests/compat/client/package.json` (new): `{ "type":"module", "dependencies":{"better-auth":"latest"} }` for the harness.
- Manual alternative: `cd goauth && go test ./src/tests/compat -run TestOfficialBetterAuthClient -count=1` (skips if `node` missing). Documented in `src/tests/compat/client/*.mjs`.

## What remains / next steps

### Org - wire services & routes (follow-up PR)
1. Services: `ITeamService`/`IOrganizationRoleService` (or extend `IOrgService`) respecting `OrgConfig.Teams`/`DynamicAccessControl` caps (maximumTeams, maximumMembersPerTeam, allowRemovingAllTeams). `invitation.teamId` validation when `Teams.Enabled`.
2. Middleware: `RequireOrgMember` permission check - static roles vs `ac` + dynamic `organizationRole.permission` JSON. Gate behind `DynamicAccessControl.Enabled`; otherwise fall back to `OrgMemberRole` owner/admin/member. `AuthorizeOrg` already 403 on role mismatch; add permission document evaluation.
3. Huma routes: `team` CRUD (`/organization/team/create`, `/organization/team/update`, `/organization/team/delete`, `/organization/team/list`, `/organization/team/addMember`, `/organization/team/removeMember`) and `organizationRole` CRUD. Return 404 when `Teams`/`DynamicAccessControl` disabled. Wire `activeTeamId` into session claims (`CustomClaims.ActiveTeamID` exists, needs resolver propagation).

5. Tests: extend `src/plugins/org/test/*` with team/role happy paths and disabled-flag 404s; add `teamMember` to compat fixtures if better-auth covers it.
