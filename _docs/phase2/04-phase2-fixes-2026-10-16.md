# Phase 2 Fixes — 2026-10-16

Branch: `feat/improvements-1-10` (3 commits beyond `5312c9e`).

## What was fixed

### 1. `Extras` removed from `InitContext`

**Done.** `Extras map[string]any` is commented out with a note:

> We do not use this field; all dependencies are provided via the typed fields above (DB, CookieManager, SecondaryStorage, SessionManager, etc.). Only re-enable with explicit justification.

All `Extras["db"]` / `Extras["sessionManager"]` / `Extras["secondaryStorage"]` fallbacks deleted in:

- `src/plugins/access-token/access_token.plugin.go` — `txMgr`, `secStorage`, `sessMgr` now read only `ictx.DB` / `ictx.SecondaryStorage` / `ictx.SessionManager` (typed).
- `src/plugins/jwt/jwt.plugin.go` — same.
- `src/plugins/access-token/test/access_token_test.go` — `InitContext` literal now sets `DB`, `SecondaryStorage` directly.
- `goauth/goauth.go` — `InitContext` construction no longer populates `Extras`.

If you believe this is wrong: the alternative is to keep `Extras` as an escape hatch for third-party plugins that need to pass custom data (e.g. a tracing provider). That is valid, but it encourages stringly-typed coupling; a better alternative is to add typed fields to `InitContext` for each new need, or use `GoAuthOptions.Extras` with a typed registry behind it. Commented-out `Extras` makes that choice explicit.

### 2. Revocation prefix unification

**Done.** Core vs plugin ownership clarified:

- Core (`src/providers/sec-storage/keys.go`) now owns only:
  `ActiveSessionsPrefix = "active-sessions-"` and `RevokedSessionPrefix = "revoked:session:"`.
- `LegacyBlacklistPrefix` and `RevokedTokenPrefix` deleted from core. `LegacyBlacklist` compat read removed from `access_token.plugin.go` middleware; `IsTokenBlacklisted` is now a no-op (interface compat stub) in both `src/providers/revocation_store.go` and `src/common/middleware/funcs.go`.
- Plugin-owned `sid:` prefix moved to `src/plugins/access-token/keys.go` (`accesstoken.SidPrefix = "sid:"`). `access_token.plugin.go` now uses `SidPrefix` constant; `src/plugins/access-token/services/serv.session.go` keeps its local `sidKey` helper (same value, no duplication across packages — acceptable).

Alternative considered: keep `LegacyBlacklistPrefix` longer for rolling deploys. Rejected: no writer for it remains, so reads would never hit; keeping it adds dead code and invites new writers to the wrong prefix.

### 3. Cache errors: `logger.ErrorCtx` + otel counter

**Done.** Previously `slog.Warn` only (or swallowed).

- New `src/app/services/session/metrics.go`: `otel.Meter("goauth/sessions")` + `goauth.sessions.cache_errors` `Int64Counter`, no-op if provider absent, plus `incCacheError(ctx)`.
- `src/app/services/session/manager.go`: `cache` backfill failure now logs `logger.ErrorCtx(ctx, ...)` + `slog.Warn` + `incCacheError`.
- `src/app/services/session/manager.go:DeleteUserSessions` and `manager-sec-store.go`: `saveActive`, `untrackActive`, `RefreshUser` all upgraded to `ErrorCtx + Warn + incCacheError`.

If you think `ErrorCtx` is noisy: a better alternative is to keep `Warn` for backfill and `Error` only for operations where the caller would otherwise think success (e.g. `Delete`). Current choice logs `ErrorCtx` for all so the otel counter is the discriminator; filter by `code` in your log pipeline if needed.

### 4. Middleware error mapping → `autherr.*` with RespCode (wire compat)

**Done.** `src/common/middleware/middleware.go`:

- `writeAuthError` now takes `*autherr.AuthError` and encodes it as `{"code","message"}` with `StatusCode` from the registry (better-auth wire format). `writeAuthErrorMsg` removed.
- `Authenticate` (missing/invalid token, revoked lookup) → `ErrUnauthorized` (401 `UNAUTHORIZED`).
- Revoked session → `ErrUnauthorized` (401). Alternative `ErrSessionExpired` (400) is the wrong status for revocation; better-auth returns 401 for revoked sessions. (If you want a distinct code for revoked-vs-missing, register `ErrSessionRevoked = Err(401, "SESSION_REVOKED", ...)` and use it here — currently collapsed to `UNAUTHORIZED` to match upstream's inline 401.)
- `Authorize` / `AuthorizeOrg`: missing claims → 401 `UNAUTHORIZED`; insufficient role/permission → 403 `FORBIDDEN` (`ErrForbidden`). Previously all were 401 `Not Authorized`, which hid authorization failures behind authentication failures.

Verified: `go test ./src/tests/compat -count=1` passes; goldens expect `code: "UNAUTHORIZED"` for unauthenticated, so no golden change required. Clients matching error codes now receive canonical codes; clients matching the old `"Token Not Valid"` string should migrate to `code`.

### 5. GoAuth read-only

**Partially done as requested, reverted to non-breaking.** Making `GoAuth` fields private would break `env.Auth.Sessions`, `s.Auth.Options`, `s.Auth.Cookies`, etc. across `src/tests/compat`, `src/tests/helpers`, `src/example/main.go` and every plugin test. Instead:

- `GoAuth` struct fields stay exported (no API break), with a top-level doc: “Fields are read-only after `SetupGoAuth` returns; mutating them is not supported.”
- Backlog: if you want true read-only, add private fields + accessor methods (`Options()`, `Sessions()`, …) and deprecate field access with a `go vet` check or wrapper type; do it with a codemod that rewrites `x.Sessions` → `x.Sessions()` in one commit. Doing it now without the codemod would just break tests.

Better alternative overall: freeze `GoAuth` by construction — return an interface, not a struct — but that is a larger change for `phase1/04-plan` backlog.

### 6. Bearer `RequireSignature` warning

**Done.** Default stays `false` (Better Auth compat) per spec, but:

- `src/plugins/bearer/config/config.go` documents the default as intentional and warns a future major will flip to `true`.
- `src/plugins/bearer/bearer.plugin.go:Init` emits `slog.Warn("bearer: RequireSignature is disabled — unsigned bearer tokens will be accepted; enable it to require HMAC-signed tokens")` when `!RequireSignature`.

If you think a warning is spammy: set `BearerConfig{RequireSignature: true}` explicitly to silence it. That is the intended “fix” without a breaking change.

### 7. Tests & DX (item 10)

**Done (remaining after prior partial).**

- `log.Fatalf` → `t.Fatalf` in `src/tests/helpers/setup.go` (10 sites: postgres/redis/sqlite/admin/org/auth init). `containerToCleanup` `panic` → `t.Fatalf`. Unused `import "log"` removed.
- Added `doJSONWithT` (test-aware variant with `t.Helper` + `t.Fatalf`); `doJSON` kept for non-test call sites (panic remains — caller is outside `testing.T`).
- Added `src/app/services/session.ManagerOption` + `WithClock(func() time.Time)` and `WithOptions` + variadic `NewManager(..., opts ...ManagerOption)` so tests can inject a clock without `mgr.now = fn` hack.
- Added `.golangci.yml` (version 2, linters: `errcheck`, `govet`, `staticcheck`, `ineffassign`, `unused`, `bodyclose`, `noctx`, `contextcheck`).
- Added `SecureCookiesCached()` / `CookieDomainCached()` in `src/config/options.go` plus `cachedSecure`/`cachedCookieDomain`/`cachedDomainOnce` on `AuthConfig`; `AuthConfig.SetDefaults()` now caches `SecureCookies`/`CookieDomain` to avoid `url.Parse` per request. (Critique: caching on `AuthConfig` is mutable state on a value that may be copied — acceptable because `SetDefaults` mutates the original `opts.AuthConfig` before it is stored; copying after setup still carries the cached values. A cleaner alternative would be to compute `secure`/`cookieDomain` on `cookies.Manager` at construction and remove `AuthConfig.SecureCookies()`/`CookieDomain()` entirely — leave that for the cookie-cache step.)

If you expected `panic` in `doJSON` to become `t.Fatalf` everywhere: that would require threading `*testing.T` into `TestEnv`; `doJSONWithT` covers test call sites without changing the `PostJSON`/`GetJSON` signatures.
